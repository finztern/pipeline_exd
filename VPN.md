# VPN по подписке (управляемый режим)

Контейнер `vpn` (sing-box) сам берёт узлы из подписки, выбирает те, через которые **реально проходит запрос к API Exorde**,
держит несколько лучших про запас и переключается при отказе. Через него идут все внешние запросы пайплайна.

## Как это работает

1. **Подписка.** `SUBSCRIPTION_URL` скачивается при старте и каждые `SUB_INTERVAL` (30 мин). Формат: список ссылок `vless://`,
   `hysteria2://` (в base64 или обычным текстом). Если набор узлов изменился, конфиг sing-box перестраивается и он перезапускается
   (проверка `sing-box check` до замены; при ошибке остаётся прежний конфиг). Если подписка недоступна, берутся сохранённые ссылки
   (том `vpn_state`), затем `vpn.txt`. Ссылка секретная и нигде не логируется.
2. **Замер.** Раз в `MEASURE_INTERVAL` (10 мин) каждый узел проверяется *через собственный локальный вход* (порты 10800+, только
   `127.0.0.1`): 1-й этап быстрая проверка (HEAD к API), 2-й этап для лучших по скорости `TOP_M`: реальная загрузка (multipart POST
   на 128 КБ x2, как у транзакционера, с вашим `MAIN_ADDRESS`). Узел годится, если API отвечает без `403/407/451/5xx` и не ломает
   multipart. Скорость = медиана времени POST.
3. **Запас.** `TOP_K` (5) самых быстрых рабочих узлов. Лучший активен (selector `proxy` через Clash API sing-box), остальные в запасе.
4. **Отказ.** Каждые `WATCH_INTERVAL` (5 с) запрос к API через общий вход (`vpn:1080`) ровно так, как ходят сервисы. Две неудачи
   подряд: узел уходит на `NODE_COOLDOWN` (5 мин), включается следующий живой из запаса, разорванные соединения клиенты повторяют.
   Если запас пуст, сразу запускается полный замер. Запасные узлы проверяются раз в минуту.
5. **Стабильность.** На более быстрый узел переключаемся, только если он быстрее текущего минимум на 20% (`SWITCH_MARGIN`).

Прямого выхода (`direct`) в конфиге нет: трафик не может «утечь» мимо VPN.

## Включение

В `.env` (ссылку подписки вставляйте только в `.env`, не в репозиторий):

```
SUBSCRIPTION_URL=<ваша ссылка>
VPN_MANAGED=true
COMPOSE_PROFILES=local-vpn          # если встроенный vpn запускается профилем
# по желанию, чтобы и загрузка моделей шла через VPN:
USE_PROXY_BPIPE=true
USE_PROXY_UPIPE=true
USE_PROXY_TRANSLATOR=true
HF_PROXY=http://vpn:1081
```

```bash
git pull
docker compose up -d --build vpn transactioneer collector
```

`VPN_MANAGED=true` включает у транзакционера режим «только через `socks5h://vpn:1080`» (без прямого выхода и без маршрутов по
узлам из `vpn.txt`), а у collector проверку дублей URL (`url-check.exorde.network`) через `http://vpn:1081`.

Без `SUBSCRIPTION_URL` всё работает по-старому (статический режим по `vpn.txt`).

## Что идёт через VPN

* выгрузка в API (транзакционер): да, единый вход `vpn:1080`;
* проверка дублей URL (collector): да (`URL_DEDUP_PROXY`, включается сама при `VPN_MANAGED=true`);
* скачивание моделей (bpipe/upipe/translator/HF): при `USE_PROXY_*=true` и `HF_PROXY`;
* обмен между своими контейнерами (collector, upipe, bpipe, переводчики): нет, это внутренняя сеть Docker;
* скрейперы (reddit и т. п.) живут вне этого compose-файла: их надо направить на `socks5h://<хост>:1080` самим
  (порт опубликован на `127.0.0.1`; для другой машины пробросьте или привяжите на нужный адрес).

## Мониторинг

```bash
curl -s localhost:9091/status | python3 -m json.tool   # активный узел, запас с оценками (мс), время последних замеров, счётчики
curl -s localhost:9091/health                           # 200, если sing-box жив, узел выбран и API через него отвечает
curl -s localhost:9091/remeasure                        # запустить полный замер сейчас
docker logs -f vpn | grep -E "🔀|🛣|🚨|📥|🔧"
```

В логе: `📥` подписка получена, `🔧` sing-box перезапущен (набор узлов изменился), `🛣` итог замера, `🔀` смена активного узла и
причина, `🚨` отказ активного узла.

## Параметры (все необязательны)

| Переменная в `.env` | По умолчанию | Смысл |
|---|---|---|
| `SUB_INTERVAL` | 1800 | как часто обновлять подписку, с |
| `VPN_MEASURE_INTERVAL` | 600 | полный замер, с |
| `VPN_TOP_K` / `VPN_TOP_M` | 5 / 12 | размер запаса / сколько лучших проверять реальной загрузкой |
| `VPN_SWITCH_MARGIN` | 0.8 | выигрыш, нужный для смены рабочего узла |
| `VPN_WATCH_INTERVAL` | 5 | проверка активного узла, с |
| `VPN_NODE_COOLDOWN` | 300 | на сколько отстраняется узел после отказа, с |
| `VPN_MEASURE_PARALLEL` / `VPN_MEASURE_TIMEOUT` | 24 / 8 | параллельность и таймаут замера |
| `VPN_API_URL` | `http://upload.exorde.network/v1/upload` | какой адрес API проверять |
| `VPN_PCS_INSECURE` | true | узлы с `pcs=` (пин сертификата) без строгой проверки цепочки |

## Замечания и ограничения

* Узлы gRPC+TLS с `pcs=` провайдер защищает пином сертификата, который sing-box не умеет. По умолчанию для них отключается проверка
  цепочки (иначе они вообще не поднимутся); отключить это можно `VPN_PCS_INSECURE=false`.
* Поддерживается формат «список ссылок». Подписки в формате sing-box JSON и Clash YAML не разбираются (будет понятная ошибка в логе).
* Менеджер хранит в томе `vpn_state` ссылки и последний выбор (права 0600), чтобы после перезапуска быстро вернуться к лучшему узлу.
* Порты `10800+` (пробные входы по узлам) слушают только `127.0.0.1` внутри контейнера; в статическом режиме они по-прежнему открыты.

## Самопроверка

```bash
python3 vpn/selftest.py                                     # разбор подписок и ссылок
SING_BOX_BIN=/путь/к/sing-box python3 vpn/selftest.py       # + конфиг на настоящем sing-box и сквозной тест с мок-узлами
```

Сквозной тест поднимает настоящий sing-box, поддельные узлы (быстрые, средний, медленный, «API за ним отдаёт 403», мёртвый) и поддельный
API, и проверяет выбор, исключение плохих узлов, аварийное переключение и обновление подписки.
